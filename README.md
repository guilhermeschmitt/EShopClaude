# EShopClaude

A minimal e-commerce demo built as distributed microservices: Java 21 / Spring Boot services, a Vue 3 storefront, and an [Aspire](https://aspire.dev) AppHost (written in TypeScript) that runs everything locally. It was built with Claude Code using spec-driven development.

## What it does

A shopper can browse a product catalog, add products to a cart, adjust quantities, place an order, and review past orders. There is no login: on first visit the storefront generates a `buyerId` (UUID) and keeps it in `localStorage`, and that ID identifies the basket and tags every order.

```
Browser ──► storefront (Vue 3 + Vite)
               │  Vite dev proxy, /api/{service}/* → service
               ├─ /api/catalog/*  ─► catalog  ──► PostgreSQL: catalogdb
               ├─ /api/basket/*   ─► basket   ──► Redis
               │                       ├─HTTP─► catalog  (product lookup on add)
               │                       └─HTTP─► ordering (create order on checkout)
               └─ /api/ordering/* ─► ordering ──► PostgreSQL: orderingdb
```

| Component | Stack | Responsibility |
|---|---|---|
| **catalog** | Spring Boot, JPA, Flyway, PostgreSQL | Read-only product catalog: paging, category filter, name search. Seeds about 24 sample products on first start. |
| **basket** | Spring Boot, Spring Data Redis | Baskets per buyer. Looks up name and price in Catalog when an item is added, and orchestrates checkout. |
| **ordering** | Spring Boot, JPA, Flyway, PostgreSQL | Persists and serves orders. Never calls other services. |
| **storefront** | Vue 3, Vite, vue-base | Pages: products (`/`), cart (`/cart`), checkout (`/checkout`), my orders (`/orders`), order detail (`/orders/:id`). |
| **AppHost** | Aspire (TypeScript, `src/apphost.mts`) | Starts PostgreSQL (with pgAdmin), Redis, the three services and the storefront, and wires their configuration. |

Services talk over synchronous HTTP only, and each one owns its own data store. Every Java service ships the OpenTelemetry Java agent, so traces, logs and metrics show up in the Aspire dashboard. The checkout trace (basket → ordering → PostgreSQL) is the one to look at.

Login, payments, stock, shipping and deployment are deliberately out of scope. The full behavior is described in [`_agenticdev/PROJECT.md`](_agenticdev/PROJECT.md).

## Requirements

To run the application:

- **Docker** (Docker Desktop or compatible), running. PostgreSQL, Redis, pgAdmin and the three Java services all run as containers, and the Java services are built inside Docker, so you don't need Java installed just to run the app.
- **Node.js** 20.19+, 22.13+ or 24+, with npm.
- **Aspire CLI** 17. Install instructions: <https://aspire.dev>. Check with `aspire --version`.

To develop and run the Java tests, you also need:

- **JDK 21**
- **Maven 3.9+** (the projects have no Maven wrapper)

## How to run

From the repository root:

```bash
cd src
npm install
aspire run
```

The first run takes a few minutes: Aspire pulls the PostgreSQL, Redis and pgAdmin images, builds the three Java images, and installs the storefront's npm packages.

When it's up, the terminal prints the **Aspire dashboard** URL (with a login token). In the dashboard:

- Wait until every resource is **Healthy**: PostgreSQL (`postgres`, `catalogdb`, `orderingdb`), pgAdmin, `redis`, `catalog`, `ordering`, `basket` and `storefront`.
- Open the **storefront** endpoint to use the shop.
- Open the **pgAdmin** endpoint to browse `catalogdb` and `orderingdb`.
- Use **Traces**, **Structured logs** and **Metrics** to see the services' telemetry.

Press `Ctrl+C` in the terminal to stop everything.

## Development

AppHost checks, from `src/`:

```bash
npm run build   # eslint + tsc on apphost.mts
npm run lint    # eslint only
```

`src/.aspire/modules/aspire.mts` is generated by the Aspire CLI from the packages in `src/aspire.config.json`, so run `aspire run` at least once before building the AppHost.

Java services, from the repository root (Testcontainers-based tests need Docker running):

```bash
mvn -f src/java-back/catalog/pom.xml test
mvn -f src/java-back/basket/pom.xml test
mvn -f src/java-back/ordering/pom.xml test
```

Storefront, from `src/vue-front/storefront`:

```bash
npm install
npm run build   # vue-tsc + vite build
```

Run the storefront through `aspire run` rather than `npm run dev` on its own: the Vite proxy only forwards `/api/*` when Aspire injects the service URLs.

## How it was built

The project follows a spec-driven workflow with Claude Code: each sub-feature is a numbered spec in `_agenticdev/microservices/<service>/`, implemented on its own branch and merged to `main` once its Definition of Done passes. See [`_agenticdev/WOW.md`](_agenticdev/WOW.md) for the workflow and [`CLAUDE.md`](CLAUDE.md) for conventions and commands.
