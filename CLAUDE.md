# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Source of truth

- `_agenticdev/PROJECT.md` defines the system's behavior: APIs, data model, checkout flow, env contract and what is out of scope. Read the relevant section before you implement anything.
- `_agenticdev/PLAN.md` orders the work into numbered steps (e.g. `3.1`). Each step has its own **Verify** list.
- Workflow: one step = one branch off `main`, named `feature/<step-id>-<slug>`. Merge only when that step's Verify list passes. Don't add features listed as out of scope in PROJECT.md §9 (auth, retries, gateway, events, stock, order status, and so on).

## Commands

The AppHost is in `src/`. Run these from `src/`:
- `npm run build`: eslint plus `tsc` on `apphost.mts`. This is the "AppHost build" check.
- `npm run lint`: eslint only. It enforces `no-floating-promises`, so every builder call must be awaited.
- `aspire run`: starts every resource and the Aspire dashboard. Docker must be running.

Java services (`src/java-back/{catalog,basket,ordering}`) are standalone Maven projects with no wrapper and no parent aggregator:
- Tests: `mvn -f src/java-back/<service>/pom.xml test`. Testcontainers-based tests need Docker.
- Run a single test: `mvn -f src/java-back/<service>/pom.xml test -Dtest=ClassName#method`
- Image: `docker build src/java-back/<service>`

The storefront (`src/vue-front/storefront`, planned) will use `npm run build` and `npm run dev`.

## Architecture

- **AppHost is TypeScript, not C#.** `src/apphost.mts` imports `./.aspire/modules/aspire.mjs`, which is generated by the Aspire CLI from the packages in `aspire.config.json`. To find the builder API (endpoints, reference expressions, `withEnvironment`, and so on), read `src/.aspire/modules/aspire.mts`; don't guess from the C# Aspire docs. Add Aspire hosting packages, such as `Aspire.Hosting.PostgreSQL` and `Aspire.Hosting.Redis`, to `packages` in `aspire.config.json`.
- **Java services run as containers** through `addDockerfile`. Each one listens on container port 8080 and has a `/health` HTTP health check, which actuator serves because `management.endpoints.web.base-path` is `/`. They are never run directly with `mvn spring-boot:run` under Aspire.
- **Observability:** each Dockerfile downloads the OpenTelemetry Java agent and starts with `-javaagent`. `withOtlpExporter()` injects the `OTEL_*` env vars. `withCertificateTrustEnvironment('OTEL_EXPORTER_OTLP_CERTIFICATE')` is required because the JVM ignores `SSL_CERT_DIR`; without it the agent can't reach the HTTPS dashboard endpoint.
- **Env contract:** Aspire's connection strings are not JDBC, so the AppHost must build `SPRING_DATASOURCE_URL/USERNAME/PASSWORD` (catalog, ordering) and `SPRING_DATA_REDIS_HOST/PORT` (basket only) itself. Basket reaches its peers through `services__catalog__http__0` and `services__ordering__http__0`, which `application.yml` maps to `catalog.url` and `ordering.url`.
- **Communication:** synchronous HTTP only. Basket calls Catalog (product lookup when an item is added) and Ordering (order creation at checkout). Catalog and Ordering never call other services. The browser only talks to the storefront origin, and the Vite proxy forwards `/api/{service}/*` with that prefix stripped.

## Java conventions

- Spring Boot **4.x** (`spring-boot-starter-parent` 4.2.0). The starters are `spring-boot-starter-webmvc` and `spring-boot-starter-webmvc-test`, and `@AutoConfigureMockMvc` is imported from `org.springframework.boot.webmvc.test.autoconfigure`. These names differ from Boot 3.
- Java 21. The base package is `br.com.guilherme.eshop.<service>`, with the layers `api` (controllers and DTO records), `domain`, `repository` and `client` (basket only, using `RestClient`).
- No Spring Security. Catalog and Ordering use JPA with Flyway migrations in `src/main/resources/db/migration` and `ddl-auto=validate`. Basket uses Spring Data Redis only.
- Tests use JUnit 5 and Spring Boot Test, with Testcontainers for Postgres or Redis. Basket stubs its peers with `MockRestServiceServer`.
